# GitHub Issues

Use issues for durable work that should survive a conversation or PR.

## Rules

- Search for duplicates before creating an issue.
- State the observed behavior, expected behavior, evidence, and scope.
- Use labels/assignees only when repository conventions support them.
- Close with the appropriate state reason and link the resolving commit/PR.

## PMCRO

An issue can carry an earned constraint or unresolved gate, but it is not itself a Checker verdict. Keep evidence links explicit.
